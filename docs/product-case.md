# 产品案例：先验证记录体验，再原生化

## 问题

睡眠时间、每周运动、阅读摘录和体重不是同一种数据。统一的“完成/未完成”按钮难以表达这些行为；加入过多功能又会让日常记录变重。

## 解决方式

- 今天：快速记录，展示对应计划与实际值。
- 统计：从同一记录源计算周、月、季、年变化。
- 记录：只收纳有文字或图片的阅读、运动、梦境内容。
- 设置：管理习惯、频率、顺序、语言与 AI 偏好。

## 产品推进路径

最初通过 Web/PWA 反复调整体验；冻结已确认的流程后，再用 React Native、Expo Router 和 SQLite 实现 iPhone 版本。PWA 承担产品探索，原生版本承担文件持久化、安全凭据存储和安装生命周期验证。

## 四个具体取舍

| 问题 | 选择 | 为什么 |
| --- | --- | --- |
| 每周三次运动是否每天都算一次失败 | 按周目标累计 | 频率规则与用户计划一致 |
| 阅读是否每次都必须上传图片和调用 AI | 保留直接保存入口 | 数值打卡也应独立有用 |
| 纯体重数值是否进入内容记录页 | 留在统计与对应历史入口 | 内容页聚焦值得回看的文字和图片 |
| AI 失败是否阻断保存 | 保留输入与手动保存 | 核心记录能力不依赖服务可用性 |

## 我的工作与 AI 协作

用具体页面方案确定体验；把选择转化为频率、存储和验收约束；通过反复使用和测试追踪错误。AI 协助编码、排查与整理材料，交付仍须依据实际行为判断。

## 证据与限制

原项目已有 PWA 试用记录、App 实现和自动检查记录，见验证说明。尚未公开外部用户数量、留存或付费数据，因此本案例不作市场验证成功的结论。
